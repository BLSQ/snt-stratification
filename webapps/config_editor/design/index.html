1 · Country and DHIS2 instance

The instance comes first: it frames every UID entered afterwards. Identity and the three administrative levels follow. All but the name are required.

UIDs are specific to the instance they come from. Data elements in a national HMIS and in a malaria registry have different UIDs even when they hold the same data. This is provenance only — it is recorded in the save log and never written into SNT_config.json. The app reads the workspace's connection list; it never opens a connection and never contacts DHIS2.

2 · Population indicators

Fixed 8-key vocabulary. Only POPULATION has a real consumer today. An empty key produces no column at all — unlike routine indicators, which produce an empty one. Several UIDs in one key are summed.

3 · Routine indicators

Each key becomes a column in {CC}_routine.parquet. Several UIDs are summed. A bare UID totals every category combo; UID.COC narrows to one. At least one UID overall is required.

Other key — escape hatch

Adds a key outside the controlled vocabulary. It will be extracted and become a column, but no active pipeline reads it.

4 · Reporting rates

The extract code checks the dataset branch first and only falls through to indicators, so the two are mutually exclusive. "None" is legitimate.

Dataset UIDs

One DHIS2 dataset UID per chip. The METRICS type block is fixed and added automatically.

⚠️ Semantics unresolved — some countries hold dataset UIDs here, one holds indicator UIDs. Collected as a free list until the SNT team decides. Not validated by the pipelines; a wrong value degrades silently.
